# Next.js 16 conventions — what differs from what you probably remember

**This project runs Next.js 16.3.0, React 19.2.4, Tailwind CSS v4.**

`AGENTS.md` warns that this version has breaking changes versus older knowledge. It
does. Everything below was verified against the bundled docs at
`node_modules/next/dist/docs/` and against the actual type declarations in
`node_modules/next/dist/` — not assumed. Re-verify after any Next upgrade.

## The traps, in rough order of how much time they cost

| Thing | Reality in 16.x |
|---|---|
| `middleware.ts` | **Renamed to `proxy.ts`** at the project root. Single exported function (default, or named `proxy`). Runtime is **Node.js and cannot be configured** — `export const runtime` in it *throws*. `skipMiddlewareUrlNormalize` → `skipProxyUrlNormalize`. Type helper: `NextProxy` from `next/server`. |
| `cookies()`, `headers()`, `draftMode()` | **async**. Synchronous access was *removed* in 16, not deprecated. |
| `params`, `searchParams` | **Promises** in page / layout / route / `generateMetadata`. Client Components cannot be async — use `use(params)` from React. |
| Route prop types | Global helpers, **no import**: `PageProps<'/accreditation/[doc]'>`, `LayoutProps<'/x'>`, `RouteContext<'/api/x/[id]'>`. Generated by `next dev`/`next build`/`next typegen`. If your editor says they don't exist, run `npm run typegen`. |
| `revalidateTag` | Second argument is **required**: `revalidateTag(tag, 'max')`. The one-arg form is deprecated. |
| `updateTag()`, `refresh()` | **Server Actions only.** Not route handlers, not Client Components. From `next/cache`. |
| `next/image` `priority` | **Deprecated → `preload`.** And `preload` belongs on **exactly one image site-wide** (the LCP candidate). The docs explicitly warn against more; competing preloads defeat the point. Everything else above the fold gets `loading="eager"`. |
| `images.qualities` | Defaults to **`[75]` only**. An out-of-list `quality` prop is silently coerced to the nearest allowed value. |
| `images.minimumCacheTTL` | Default changed 60s → **4 hours**. |
| Smooth scrolling | Next **no longer overrides `scroll-behavior`** during router navigation. CSS alone is insufficient — `<html>` also needs `data-scroll-behavior="smooth"`. |
| `serverActions` config | Still under **`experimental`** in 16.3.0 (verified in `config-shared.d.ts`). `bodySizeLimit` defaults to **1 MB**. |
| Bundler | **Turbopack is the default.** A custom `webpack` key in `next.config.ts` **fails the build**. |
| `next lint` | **Removed as a command.** `package.json` runs `eslint` directly. `next build` no longer lints. |
| Removed entirely | `experimental_ppr`, `serverRuntimeConfig`, `publicRuntimeConfig`, `next/config`, AMP. |
| `metadata.viewport` / `.themeColor` / `.colorScheme` | Deprecated → `export const viewport: Viewport`. |
| Parallel routes | Every slot **requires** a `default.tsx` or the build fails. |
| `typedRoutes` | **Stable and top-level** (`experimental.typedRoutes` is deprecated). We enable it — see the gotcha below. |
| `server-only` | Needs **no npm install** for the app; Next declares and aliases the module internally. (We *do* install it as a devDependency purely so standalone `tsx` scripts can resolve it — see below.) |

## Security: the proxy is not a security boundary

The bundled docs state it plainly: Server Functions "are handled as POST requests
to the route where they are used, so a Proxy matcher that excludes a path will also
skip Server Function calls on that path," and they are "reachable via direct POST
requests, not just through your application's UI."

So:

- `proxy.ts` does **optimistic redirects only** (does a session cookie exist?).
- `lib/dal.ts` is the **actual** enforcement point, called from every protected page
  and as the **first statement** of every protected server action.
- Never put an auth check in a `layout.tsx`. Layouts **do not re-render on
  navigation**, so the check runs once and then never again.

Next 16.2.1 shipped with 23 HIGH advisories including proxy-bypass and
server-action-disclosure issues. We upgraded to 16.3.0 (`npm audit` → 0
vulnerabilities). The architecture above means a future bug of that class does not
by itself grant access.

## `typedRoutes` gotcha

With `typedRoutes: true`, `<Link href>` and `redirect()` accept only paths that
actually exist. Shared components that take an href must therefore type it as
`Route` (`import type { Route } from 'next'`), not `string`:

```ts
import type { Route } from "next";
function ButtonLink({ href }: { href: Route }) { /* … */ }
```

For arrays mixing internal routes and `mailto:`/`tel:` links, TypeScript widens
both to `string` and fails. Use a discriminated union — see the `ContactAction`
type in `app/(marketing)/contact/page.tsx`.

## `cacheComponents` is deliberately OFF

Enabling it would remove `dynamic`/`revalidate`/`fetchCache`, require `<Suspense>`
around every uncached read (build *errors* otherwise), and forbid `use cache`
inside route-handler bodies. For a form-heavy, authenticated-read-heavy app that is
a large migration for little gain. Read
`node_modules/next/dist/docs/01-app/02-guides/migrating-to-cache-components.md`
before revisiting.

## Satori / `next/og` constraints

`app/icon.tsx`, `app/apple-icon.tsx`, and `app/opengraph-image.tsx` generate images
via `ImageResponse`. Two rules, both of which **fail the build** rather than
degrading:

1. **Flexbox only.** No CSS grid.
2. **Any element with more than one child node needs an explicit `display: flex`.**
   This includes JSX like `Est. {year}` (a string *and* an expression = two child
   nodes) and text broken by `<br />`. Give every text node its own leaf element
   with a single precomputed string.

Useful: `next/og` **bundles Geist-Regular.ttf as a default font**
(`node_modules/next/dist/compiled/@vercel/og/`), so text renders without fetching
or shipping a font file.

## Tailwind v4 notes

- **CSS-first. There is no `tailwind.config` file and there should not be one.**
  Design tokens live in the `@theme` block in `app/globals.css`.
- `@theme` for plain values; **`@theme inline`** for values referencing other CSS
  vars (the `next/font` variables), which would otherwise resolve too early.
- Tailwind's preflight already wires `--font-sans` onto `<html>`. A `font-family`
  on `body` **overrides that inherited value** — this is the bug that made the site
  render in Arial instead of Geist for its entire life. Don't reintroduce it.
- The ESLint plugin flags non-canonical classes (`z-[100]` → `z-100`). Listen to it.

## React Compiler lint

`react-hooks/set-state-in-effect` is enforced. Calling `setState` synchronously in
an effect body is an error. To reset state when a prop/pathname changes, use
React's documented **adjust-state-during-render** pattern instead — see
`app/components/SiteHeader.tsx`.

## Running TypeScript scripts outside Next

`scripts/*.ts` import modules marked `import "server-only"`, which Next aliases at
build time but plain Node cannot resolve. The working combination:

```
tsx --env-file-if-exists=.env.local --conditions=react-server scripts/x.ts
```

- `tsx` handles TS + ESM/CJS + path resolution.
- `--conditions=react-server` makes Node resolve the real `server-only` package's
  `react-server` export condition to its no-op `empty.js`.
- `--env-file-if-exists` is needed because **`.env.local` loading is a Next
  feature** — standalone Node does not do it.
